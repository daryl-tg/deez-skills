# Persona setup and editing

## Sub-features

- Explicit global profile selection, loaded preview, full-profile spotlight, fixed samples and per-profile learning permission.
- Immediate historical setup, active progress, insufficient history, resume and cancellation.
- Manual creation, structured edits, concurrent revision reconciliation and reviewed learning holds.
- Native selfmd pair or folded Markdown import; save separately from selection.
- Evidence-free default export, optional private evidence, and a private saved-voice sample.
- Direct History entry and restore, phone layout, browser Back and owner-scoped offline recovery.

- Hosted /chat/ parity over Remote Control: every Voice and Away call runs on the owner's home daemon by operation name, with unreachable-desk states (offline, remote control off, outdated, busy, no answer). On origin/main since `2a737b9e`; end-to-end use still needs a relay and home daemon that speak the `operation` verb.

## How to get to it (user POV)

Open Agents, then **Voice** in the sidebar's **Persona** group (a `nav` named "Persona sections"). Voice is the first row. With no card, choose Set up my voice now, Import a card, or Create manually. A saved setup or imported card needs Use this card before selection. An existing card offers **Edit**, Advanced document, History and Export card (measured at `f7d7c987` with `personaState=ready`; the button text is plain "Edit", `PersonaPanel.tsx:1153-1167`). Away coverage and Activity are the other two Persona rows; this surface does not arm an agent.

### Hosted /chat/ over Remote Control (on origin/main since `2a737b9e`)

In the hosted app the Persona hub reaches the home daemon through the Remote Control `operation` verb, never daemon HTTP. Source: `packages/chat-ui/src/lib/remote-operation.ts` (`remoteOperation(name, init)`), its operator registry `lib/remote-operator-registry.ts`, the copy in `lib/remote-unavailable.ts`, `RemoteControl.operation()` in `remote-control.ts`, and the cloud adapters `apps/cloud/src/lib/{local-operation,away-client,daemon-operations,om-daemon}.ts`. The daemon maps the closed name list to its routes (`@openmarket/rooms-client/remote-operation-routes`, daemon-only). The cloud dist must never contain `/api/away` or `/api/library/` (`apps/cloud/tools/check-dist.mjs`).

Driving it needs a three-hop rig: a local relay from `kiyotaka-chat-service` (Redis off, dev RS256 `JWT_KEYS`), a `control-om` lane daemon with `OM_ROOMS_WS_URL` at that relay and remote control enabled, a local store (`tharamine-user-service` on a fresh `mongo:7` replica set) for Voice data, and the cloud app under `vite` on 4178 with an out-of-repo proxy config and seeded `jwt` + `om.chat.voucher` localStorage. Start vite with `--force` after any rooms-client link change: a stale dep pre-bundle makes the lazy Remote Control chunk fail and every call reads offline. Full runbook: the task's dev-notes `rig.md` (cloud-persona-parity).

**Fixture lane (no relay).** The `/chat/` shell fixture registers no remote operator, so every call answers 503 `remote_offline` and only the offline state renders. Open `/chat/tools/visual/shell-fixture.html?view=agents&alerts=quiet` on the cloud lane, then click `button` **Voice** in `nav` **Persona sections**. The path becomes `/chat/agents/voice` and the page reads "Your desk is offline. Voice settings load when om at your desk is running." **Away coverage, status can't tell right now** goes to `/chat/agents/away` and reads "Your desk is offline. Away coverage needs om running at your desk." `?view=agent&panel=voice` does not work there: the cloud fixture has no persona mock, and its sections route on the pathname (`apps/cloud/src/lib/routing.ts:298`). The other states (off, outdated, busy, no answer: `remote-unavailable.ts:22-39`) need a registered operator or the rig below.

Unreachable states to drive: stop the lane (Voice "Your desk is offline. Voice settings load when om at your desk is running.", Away "Your desk is offline. Away coverage needs om running at your desk.", sidebar Away "Can't tell"); `om agent remote disable` on the lane ("Remote control is off at your desk. Turn it on with om agent remote enable."). For `/rooms` regression set `OM_ROOMS_GUI_DIR` on the lane to the candidate `dist/` and confirm zero relay `operation` frames.

## Gotchas

The canned fixture proves navigation and component behavior. An actual HTTP handler with a synthetic relay adapter proves API integration, not deployed relay delivery. Setup with an injected zero-history learner does not prove a paid model pass. Test durable checkpoint reuse and publication separately in the daemon suite.

The report can legitimately contain text:null for no selected card. Treat it as an empty state, not an old daemon. A missing model must leave the editor usable. Learning may remain off after setup or reviewed-baseline resume. Hand-edited empty rules must not revive stale embedded JSON. Never include private evidence in exported proof artifacts by default.

There is no cross-fork drift report: `sync-shared.ts` was deleted in `f190644c` and the persona UI is one shared implementation under `packages/chat-ui/src/`. A persona change is in `/rooms` and `/chat/` at once, so drive both hosts rather than looking for a twin to reconcile.

The actual API rig must include a synthetic HOME mirror-health entry and directory to prove managed voice skill publication. Missing mirror state should produce an unavailable load and preserve the previous selection; a 200 report by itself is not proof that the voice skill exists. Never configure that rig against the operator’s real mirror.
