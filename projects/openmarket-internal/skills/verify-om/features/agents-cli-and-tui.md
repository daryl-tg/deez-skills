`om agent` lists the agents installed on this home, shows one agent's fields and reach, changes the fields a plugin lets you change (model, description, when to use, paused, shadow), and lists or cancels agent runs. Since #2306 and #2318 it also writes, tries, grades, creates and trusts agents (`init`, `try`, `eval`, `create`, `trust`, `list --lock|--here`); those live in [agent files and scopes](./agent-files-and-scopes.md) and [om creates an agent](./agent-create.md). In `om chat` the same agents sit in a bottom overlay (ctrl+x `a`) with RUNS and AGENTS tabs, and `/agents <name>` opens one agent's page. A guest home gets six default agents from the registry a few seconds after boot.

## Sub-features

- `list`: `om agent list` prints one row per agent, `name  brain/model  state  N today  vX` (`explain     om/inherits  idle  0 today  v1.0.0`); `--format json` is `{items:[{id,name,origin,version,brain,model,toolCount,portrait,owner,avatar,paused,shadow,machine,live,turnsToday,scope,shadowedBy,removed,packageId}],lockPath}`; the text row now names the scope (`explain     plugin  om/inherits  idle  0 today  v1.0.0`) and a shadowed plugin agent reads `argue       plugin  shadowed by user`. A guest lane lists `argue`, `debugger`, `explain`, `fact-check`, `feature`, `librarian`.
- `show`: `om agent show <name>` prints `── About`, `── Reach`, `── Settings`, `── Schedules` with a source after each field (`(plugin)` or `(locked)`). Since #2435 Settings has a `Brain` row: `om` for a chat agent; for a work agent (`feature`, `debugger`) the bound brain, `claude` or `codex`, or `none, wants claude` when neither is installed. The daemon binds the first brain the agent names that is signed in, else the first installed, at start and on each sweep; it searches PATH, then `~/.local/bin`, `~/.claude/local`, `~/.bun/bin`, `~/.npm-global/bin` and the `OM_BRAIN_SYSTEM_DIRS` directories. `--format json` carries it in `fields` as `{field:"brain", value, source}`; an unknown name exits 1 `No agent named <name> is installed.` with `Run \`om agent list\` for the installed agents.`
- `configure`: `om agent configure <name>` takes `--model <id|inherit>`, `--description`, `--when-to-use a,b`, `--paused on|off`, `--shadow on|off`; text receipt `Paused   on` / `Applies  next run`, JSON `{revision,applied,appliesTo:"next run",agent,set}`. `--model` is checked before it is stored: on a home with no model credential any value is `model_provider_unavailable` (`no model credential on this home`, hint `om init connects one`); with one, an unknown provider prefix is `model_provider_unknown` (`nonsense is not a provider`, hint `use <id> or <provider>/<id>`), a bare id (`fake`) uses the home's provider, and `inherit` clears it (`set:{model:null}`). There is no CLI flag for tools, brain or kind; the action refuses those fields `plugin_owned:<field>` and a plugin-locked field `locked:<field>`.
- `ps-cancel`: `om agent ps` heads `Agents: 4 at once · R running · Q queued`; a row is `run_<8>  <agent>  <door>  <state>  <age>  <room>  <ask head>`. `om agent ps <full run id>` prints `Run:`, `Agent:`, `Door:`, `State:`, `Started:`, `Room:`, `Ask:`, `Result:`, `Proposals:`, `Events:`. The short id on a row is not accepted. `om agent cancel` refuses an unknown run `Run was not found.` and an ended one `Run already <state>.` (both exit 1).
- `engine-start` (added 2026-11-14, #2399): an engine agent (agent file `kind: engine`, installed as a companion of a registry `tool-engine` package) is started at a terminal, never by a room or a task. `om agent start <agent> --input <json|@file.json> [--profile <name>]` prints `queued <runId> (<agent>)` and `Watch: om agent status <runId>`. Refusals, JSON with exit 2:
  - a chat or work agent: `kind_unsupported` `explain is not an engine agent.`, hint `Ask it in a room or in om chat.`
  - an unknown name: `not_found` `No agent named nope.`
  - no `--input`: `run_input_invalid` `--input is required.`; `--input '[1]'`: `--input must be a JSON object.`; `--input @/missing.json`: `Cannot read /missing.json.`
  - The daemon door is `POST /rpc/v1/roster/engine-runs {id, agent, input, profile?}`. A non-engine agent is 403 `kind_unsupported`, and a body with no `id` is 400 `malformed_body` `Invalid field: id`.
- `run-status` (added 2026-11-14, #2399): `om agent status <run>` prints the same detail as `agent ps <run>` (`Run:`, `Agent:`, `Door:`, `State:`, `Started:`, `Room:`, `Ask:`, `Result:`, `Proposals:`, `Usage:`, `Events:`). `om agent status set|clear` still publish an agent's status. `om agent output <run>` prints the run's result artifact, or `No output yet.` for a run with none; an unknown run is `Run was not found.`, exit 1.
- `overlay`: ctrl+x `a` opens `agents` at the foot of the screen. RUNS (`c cancel  o open  tab agents  esc`) and AGENTS (icon, brain/model, state, runs today, version; `enter open  p pause  s shadow  m draw  / filter  tab runs  esc`). `p` asks `Save 1 field? y/n` and answers `saved, applies to the next run`. `m` asks `Draw <agent>? y/n` with `Cost  one model run each`.
- `agent-page`: `/agents <name>` (or `enter` on a row) opens tabs ABOUT, REACH, SETTINGS, SCHEDULES, RUNS; ABOUT reads `Portrait  not drawn, m to draw`, the plugin fields with their source (`plugin`, or `you` for a tuned field), `Model  inherits om's (<provider>/<model>)`, `Scope`, `Skills`, `Version`, `Trigger rate  not measured` (or `0.67 (3 asks, today)` after `agent eval`) and `Digest`; SETTINGS lists `Brain` (locked), `Model`, `Description`, `When to use`, `Paused`, `Shadow` and `Save` (`enter edit  ctrl+s save`); REACH reads `Tools`, `Vault`, `Requires` and `Widen  update the plugin`. `/agents a b` prints `Usage: /agents (your agents) · /agents <name> (that agent's page) · /agents draw (draw every agent without a portrait)`.
- `at-door`: `@<name> <ask>` in the composer hands the ask to that agent; an unknown name answers `No agent named nope. Installed agents are argue, debugger, explain, fact-check, feature, librarian`.
- `mcp`: `agent_list`, `agent_runs`, `agent_run`, `agent_run_cancel`, `agent_configure`, `agent_portrait`, and since #2303 and #2306 `agent_create`, `agent_fit`, `agent_tools`, `agent_tune`, `agent_tune_apply`, `agent_init`, `agent_try` and `agent_eval` are listed over MCP stdio (`agent_trust` is registered but on no MCP posture); `agent_run` with an unknown agent is `not_found` `No agent named zzz.` with the hint `Installed: argue, debugger, ...`.
- `motion` (source only): `chat.motion on|off` (stored as `tui.motion`, `OM_TUI_MOTION` outranks it) stills the portrait and the status line's breath; a bad value is refused `chat.motion must be on or off.`

## How to get to it (user POV)

- Terminal: `om agent list`, `om agent show <name>`, `om agent configure <name> --paused on`, `om agent ps`, `om agent status <run>`, `om agent start <engine agent> --input <json>`.
- In `om chat`: press ctrl+x then `a`, or type `/agents` or `/agents <name>`; type `@<name> <ask>` to hand an ask to one agent.

## Driving it with control-om

Preconditions: a lane the run started, `OM_LANE_PORT` exported, and the lane log's `om-skills defaults installed 8 package(s)` line (the six agents plus two skills). `om chat` needs a model; the fake model and launcher in [chat-workspace-tui.md](chat-workspace-tui.md) work.

1. `control-om om -- agent list` and `--format json`; assert six names and `live` `idle`.
2. `control-om om -- agent show explain`; assert the four section rules and `Tools  library_read, room_read (locked)`. `agent show nosuch` exits 1 with the not-installed line.
3. `control-om om -- agent configure explain --paused on --format json`; assert `applied:["paused"]`, then `agent list` reads `paused` on the `explain` row. Undo with `--paused off`.
4. `control-om om -- agent ps --format json` reads `{"runs":[],"pool":{"limit":4,...}}` on a fresh lane. To get a run without a model, fire a watch agent step ([watch-agent-step.md](watch-agent-step.md)); the run fails `No LLM API key configured` on a guest lane and `agent ps` lists it with door `watch`. Read it with `agent ps <id from --format json>`; `agent cancel <id>` exits 1 `Run already failed.`
5. In tmux: ctrl+x, `a`; `Tab` to AGENTS; move to a row; `p`, `y`; then `control-om om -- agent list` on the CLI shows `paused`. `p`, `y` again to undo. `enter` opens the page; `Tab` walks the tabs; `esc` returns to the list and `esc` closes the overlay.
6. Engine verbs on any lane: `control-om om -- agent start explain --input '{}'` exits 2 `kind_unsupported`; `agent start nope --input '{}'` exits 2 `not_found`. For `agent status` and `agent output`, start a run through the task door ([roster-task-pool.md](roster-task-pool.md)) and pass its `runId`.
7. Close the overlay before typing in the composer: while it is open, letters are its keys (`p` pause, `s` shadow, `m` draw).

## Gotchas

- `om agent` has two generations of verbs. `list`, `show`, `configure`, `portrait`, `ps`, `cancel`, `create`, `init`, `try`, `eval`, `trust`, `start`, `status` and `output` are always there on the internal entry; `runs` and `pause` (retained work runs) still need `OM_DEV=1`, and `om roster` (list, measures) is `OM_DEV=1` only.
- `agent ps` truncates the run id on a row (`run_99b0`); `agent ps run_99b0` answers `Run was not found.` Take the id from `--format json`.
- A watch-door run's `Ask:` is the step's whole `<watch_header boundary=…>` envelope, not only the ask you wrote (README gaps).
- Typing into the composer while the agents overlay is open sends keystrokes to the list. On 2026-11-04 a typed sentence opened `Draw librarian? y/n`; answer `n` and check `agent list --format json` for stray `paused`/`shadow` flags.
- Creating an agent starts a `portrait` run on it at once; on a fake model it shows in RUNS as `! <name>  portrait  failed` with the agent's own prompt as the ask.
- A guest lane's chat shows `⚠ this install holds state from 1 other account (account guest_…)` on a fresh lane home; it is unrelated to the agents.
