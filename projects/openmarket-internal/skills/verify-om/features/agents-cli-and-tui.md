`om agent` lists the agents installed on this home, shows one agent's fields and reach, changes the fields a plugin lets you change (model, description, when to use, paused, shadow), and lists or cancels agent runs. Since #2306 and #2318 it also writes, tries, grades, creates and trusts agents (`init`, `try`, `eval`, `create`, `trust`, `list --lock|--here`); those live in [agent files and scopes](./agent-files-and-scopes.md) and [om creates an agent](./agent-create.md). In `om chat` the same agents sit in a bottom overlay (ctrl+x `a`) with RUNS and AGENTS tabs, and `/agents <name>` opens one agent's page. A guest home gets six default agents from the registry a few seconds after boot.

## Sub-features

- `list`: `om agent list` prints one row per agent, `name  brain/model  state  N today  vX` (`explain     om/inherits  idle  0 today  v1.0.0`); `--format json` is `{items:[{id,name,origin,version,brain,model,toolCount,portrait,owner,avatar,paused,shadow,machine,live,turnsToday,scope,shadowedBy,removed,packageId}],lockPath}`; the text row now names the scope (`explain     plugin  om/inherits  idle  0 today  v1.0.0`) and a shadowed plugin agent reads `argue       plugin  shadowed by user`. A guest lane lists `argue`, `debugger`, `explain`, `fact-check`, `feature`, `librarian`.
- `show`: `om agent show <name>` prints `── About`, `── Reach`, `── Settings`, `── Schedules` with a source after each field (`(plugin)` or `(locked)`). Since #2435 Settings has a `Brain` row: `om` for a chat agent; for a work agent (`feature`, `debugger`) the bound brain, `claude` or `codex`, or `none, wants claude` when neither is installed. The daemon binds the first brain the agent names that is signed in, else the first installed, at start and on each sweep; it searches PATH, then `~/.local/bin`, `~/.claude/local`, `~/.bun/bin`, `~/.npm-global/bin` and the `OM_BRAIN_SYSTEM_DIRS` directories. `--format json` carries it in `fields` as `{field:"brain", value, source}`; an unknown name exits 1 `No agent named <name> is installed.` with `Run \`om agent list\` for the installed agents.`
- `configure`: `om agent configure <name>` takes `--model <id|inherit>`, `--description`, `--when-to-use a,b`, `--paused on|off`, `--shadow on|off`; text receipt `Paused   on` / `Applies  next run`, JSON `{revision,applied,appliesTo:"next run",agent,set}`. `--model` is checked before it is stored: on a home with no model credential any value is `model_provider_unavailable` (`no model credential on this home`, hint `om init connects one`); with one, an unknown provider prefix is `model_provider_unknown` (`nonsense is not a provider`, hint `use <id> or <provider>/<id>`), a bare id (`fake`) uses the home's provider, and `inherit` clears it (`set:{model:null}`). There is no CLI flag for tools, brain or kind; the action refuses those fields `plugin_owned:<field>` and a plugin-locked field `locked:<field>`.
- `ps-cancel`: `om agent ps` heads `Agents: 4 at once · R running · Q queued`; a row is `run_<8>  <agent>  <door>  <state>  <age>  <room>  <ask head>`. `om agent ps <full run id>` prints `Run:`, `Agent:`, `Door:`, `State:`, `Started:`, `Room:`, `Ask:`, `Result:`, `Proposals:`, `Events:`. The short id on a row is not accepted. `om agent cancel` refuses an unknown run `Run was not found.` and an ended one `Run already <state>.` (both exit 1).
- `engine-start` (added 2026-11-14, #2399): an engine agent (agent file `kind: engine`, installed as a companion of a registry `tool-engine` package) is started at a terminal, never by a room or a task. `om agent start <agent> --input <json|@file.json> [--from <run>[#<node>]] [--limits <json>]` prints `queued <runId> (<agent>)` and `Watch: om agent status <runId>`. Refusals, JSON with exit 2:
  - a chat or work agent: `kind_unsupported` `explain is not an engine agent.`, hint `Ask it in a room or in om chat.`
  - an unknown name: `not_found` `No agent named nope.`
  - no `--input` and no `--from`: `run_input_invalid` `--input is required.`; `--input '[1]'`: `--input must be a JSON object.`; `--input @/missing.json`: `Cannot read /missing.json.`
  - Since #2565 (source; the flag live 2026-11-18) `--limits` replaces `--profile`: this run's ceilings; since #2566 one above the package's budget asks a typed terminal yes (`Raise <agent> past its package's budget?`, one `Raise  72 -> 144 backtests` row per ceiling and a `Warning` row; with no terminal it is `confirmation_required` `A budget raise needs a yes typed at a terminal.`, and a no prints `Nothing was raised.`; live 2026-11-20 on `agent budget`, and the no-terminal refusal on `agent start --limits` too). `agent start` and `agent budget` take no `--yes` (`unknown option '--yes'`, exit 1). Refused before queueing with `limits.<c> is not a ceiling (max_tool_calls, max_backtests, run_tokens, daily_tokens).`, `limits.<c> must be a whole number of at least 1.` or `limits.<c> <n> is above om's cap of <m>.` (live 2026-11-20: `input_invalid` `limits.max_tool_calls 99999 is above om's cap of 400.`; an input the package's schema refuses is `input_invalid` `Input thesis: Invalid input: expected string, received undefined`). A run stopped at a ceiling reads `Stopped at the run's 16 tool calls.`. The package declares one `executor.budget` (`max_tool_calls` required; `max_backtests`, `run_tokens`, `daily_tokens` optional); a package still declaring `executor.profiles`/`default_profile` is no longer an engine agent. #2560's `Profile:` line and row are gone again.
  - `--from <run>` (#2580, flags and refusals live 2026-11-19) continues a finished run from its own start input, or `<run>#<node>` one node of its tree; each top-level `--input` key replaces that key, `null` deletes it, and `om agent status` adds `Continues: <run>#<node>`. Live: `--from '#n'` is `run_input_invalid` `--from #n is not a run.` (hint `Pass --from <run> or --from <run>#<node>.`); a chat agent is `kind_unsupported` first. An engine agent whose start input declares no continue is `kind_unsupported` `<agent> can't continue runs.`, hint `Its start input declares no continue.` (live 2026-11-20). Source only: `<run> is <state>; only a finished run can be continued.`, `<run> has no node <n> in its tree.`
  - The daemon door is `POST /rpc/v1/roster/engine-runs {id, agent, input, limits?}`. A non-engine agent is 403 `kind_unsupported`, and a body with no `id` is 400 `malformed_body` `Invalid field: id`.
- `local-engine-build` (added 2026-11-18, #2551, #2556): `om install <dir|tgz> --allow-local-engine` installs a local build of an agent that carries its tool engine, for its developer. It is a yes typed at the terminal: `--yes` is `terminal_required` `This install needs a yes typed at this terminal; --yes cannot answer it.` (live 2026-11-20), and `--preflight` with the flag is `invalid_args` (live). It installs as `@local/<name>`, publisher `local`, never the publisher its `plugin.json` claims; the card (live 2026-11-20) shows `Agent`, `Reach`, `Publisher  local`, `Shadow`, `Version`, `Runs  its code as you, only when you start it with om agent start`, `Engine  unverified local build, tool-engine-1`, `Sha256  <digest>`, the om tool rows and `Budget  8 tool calls, 72 backtests`, then asks `Install @local/<name>@<version> (agent-plugin)?`; a yes prints `Installed <name> <version> (agent plugin)`. A changed engine binary is refused (source), as is a local package that lists a money tool (`local_engine_money_refused` `@local/<name> declares money tools: order_place.`, hint `Remove them from the build, or install it from the registry.`; live) or pins one that reaches money (`<name> pins <coord>, which reaches money: …`; source). Without the flag a local copy is `tool_engine_publisher_refused` (live), on `--preflight` too. A successful install needs a real agent plugin folder, not the engine-only fixture; the recipe is under Driving.
- `engine-budget` (added 2026-11-19, #2566; refusals live, the rest source): `om agent budget <agent> [budget] [--clear]` shows or sets your own budget for an engine agent (`e.g. '{"max_backtests":72}'`; `--clear` goes back to the package's). With no budget it prints `Budget:` and `Your budget:` (`none, runs take the package's` when unset; `--format json` or a pipe gives `{agent, budget, ownerBudget}`), and `om agent show` gains `Budget`, `Your budget` and `Warning` rows (live 2026-11-20: `Warning  72 backtests may be throttled or refused on Guest (600 weight/60s, 7 days of history)`; since #2600 the day count comes from the key's plan tier, 365 on Plus). A budget below the package's saves with no question (`Your budget   36 backtests`), and `--clear` returns it to `none` (live). A raise past the package's budget asks the same terminal yes as `--limits` (live); the daemon refuses an unconfirmed one `raise_unconfirmed` (source). A plain uninstall drops your budget: after a reinstall it read `none` again (live). Budget refusals are `bad_request`: `budget.<c> must be a whole number of at least 1.`, `budget.<c> is not a ceiling (…)`. Live refusals, JSON exit 2: `nope` `not_found` `No agent named nope is installed.`; a chat agent `kind_unsupported` `explain is not an engine agent.`; a budget with `--clear` `bad_request` `Give a budget or --clear, not both.`; `x` `run_input_invalid` `budget is not JSON.`
- `plan-facts` (#2558, source only): an engine package that declares `"context": ["plan_facts"]` shows `Reads: your data plan (tier, history, rate limit)` on its install card (`reads your data plan (new)` on an update), and its runs carry `[plan: free · history 30d · 3000 weight/60s]` before the ask (since #2600 the days follow the key's tier: 7 for a guest or a legacy `free` claim, 30 Free, 90 Basic, 365 Plus and Advanced). `plan_facts` is on no catalog and no MCP face (`Tool plan_facts not found`, live 2026-11-19).
- `run-status` (added 2026-11-14, #2399): `om agent status <run>` prints the same detail as `agent ps <run>` (`Run:`, `Agent:`, `Door:`, `State:`, `Started:`, `Room:`, `Ask:`, `Result:`, `Proposals:`, `Usage:`, `Events:`). An engine run reads `Door: engine` and `Ask: Start the engine run with the input above.`; live 2026-11-20 a completed one read `Result: completed, <answer>`, `Stopped: the agent finished` and `Usage: 1 tool call, 280 tokens, $0.0000`, and one started with no model read `State: failed`, `Error: run_failed`, `Why: No LLM API key configured. …`. `om agent output <run>` printed the engine tool's result JSON. `om agent status set|clear` still publish an agent's status. `om agent output <run>` prints the run's result artifact, or `No output yet.` for a run with none; an unknown run is `Run was not found.`, exit 1.
- `engine-followups` (#2499, on main 2026-11-16; the flags live 2026-11-17 at `8e350d253a`, the rest source only): `om agent output <run> --tree` prints an engine run's search tree (`--help`: `Print an engine run's search tree instead`). `om agent status <run>` adds `Stopped: the agent finished`, `Stopped: it used every round it had`, `Stopped: the engine said <reason>` or `Stopped: <ceiling> ceiling` (none on a failed run). Since #2588 a plain `om uninstall <package>` keeps an engine agent's engine data and its runs, and a reinstall brings the runs back under the same agent (live 2026-11-20: card rows `Deletes: agent, credential, engine`, `Keeps: engine data and 5 runs, for a reinstall` and `Reinstall any time: om install @local/<name>`; after the yes `Kept: engine data and 5 runs, for a reinstall`; `agent ps` still listed the 5 runs, before and after the reinstall; the runs part is left out at 0, source). `--forget-ledger` (help: `Also delete what the package keeps for a reinstall (an agent's engine data and runs)`) deletes both: the card's row read `Deletes: agent, engine, engine data, 5 runs and their outputs` and `agent ps` then listed none (live; `1 run and its output` for one, source). #2583 lets `om install <pkg> --replace` with a same-version rebuild relock the agent, so `om agent start` no longer refuses `on disk does not match the agent's install` (source). An engine package's `executor.om_tools` lists up to 8 om tools, and since #2608 any registered action, not reads only. The install card names what each does (live 2026-11-20): `Om tools  markets, news_catalog (read-only)` when every tool reads public data (market data, Polymarket, news, research); otherwise `Om tools  markets, backtest_sweep, memory_search` with no suffix, plus `Writes  backtest_sweep, without asking you`, `Reads yours  memory_search, sent to its engine` and, for a tool above tier 2 or one that reaches capital, `Asks you  <names>, held for your yes on each call` (source; a local build refuses a money tool outright). A registry build's `Runs` row reads `with the om tools below, …` in place of `read-only, …` (source). The only install refusals left are an unknown name (`<name> is not an om tool.`, live) and a fact read with no matching `context` (source). In a run the model is handed the package tools and the listed om tools together; a listed read or tier-2 write runs without asking (live: `memory_search`, `markets`), a tool not listed answers `Unknown tool: <name>.` and the run's status adds `Error: capability_missing` / `Why: <agent> cannot call <name>: its manifest has no <name>` (live), and a held tool is saved as a proposal (source). An update card adds `om tools: + <names>` and one line per risky tool (source). The install card carries one `Budget:` row, and `om package update` asks again when a ceiling rises or drops (`budget: 16 -> 32 tool calls`; the per-profile `focused: 2 -> 4` form is gone with #2565). An uninstall of a package that is not installed is `not_installed`. `om agent output <run> --tree` on a run with no tree prints `No tree for this run.` (live). ## How to get to it (user POV)

- Terminal: `om agent list`, `om agent show <name>`, `om agent configure <name> --paused on`, `om agent ps`, `om agent status <run>`, `om agent start <engine agent> --input <json>`.
- In `om chat`: press ctrl+x then `a`, or type `/agents` or `/agents <name>`; type `@<name> <ask>` to hand an ask to one agent.

## Driving it with control-om

Preconditions: a lane the run started, `OM_LANE_PORT` exported, and the lane log's `om-skills defaults installed 8 package(s)` line (the six agents plus two skills). `om chat` needs a model; the fake model and launcher in [chat-workspace-tui.md](chat-workspace-tui.md) work.

1. `control-om om -- agent list` and `--format json`; assert six names and `live` `idle`.
2. `control-om om -- agent show explain`; assert the four section rules and `Tools  library_read, room_read (locked)`. `agent show nosuch` exits 1 with the not-installed line.
3. `control-om om -- agent configure explain --paused on --format json`; assert `applied:["paused"]`, then `agent list` reads `paused` on the `explain` row. Undo with `--paused off`.
4. `control-om om -- agent ps --format json` reads `{"runs":[],"pool":{"limit":4,...}}` on a fresh lane. To get a run without a model, fire a watch agent step ([watch-agent-step.md](watch-agent-step.md)); the run fails `No LLM API key configured` on a guest lane and `agent ps` lists it with door `watch`. Read it with `agent ps <id from --format json>`; `agent cancel <id>` exits 1 `Run already failed.`
5. In tmux: ctrl+x, `1` (it opens on AGENTS; `Tab` toggles RUNS, where `enter` on a run opens the run view); move to a row; `p`, `y`; then `control-om om -- agent list` on the CLI shows `paused`. `p`, `y` again to undo. `enter` opens the page; `Tab` walks the tabs; `esc` returns to the list and `esc` closes the overlay.
6. Engine verbs on any lane: `control-om om -- agent start explain --input '{}'` exits 2 `kind_unsupported`; `agent start nope --input '{}'` exits 2 `not_found`. For `agent status` and `agent output`, start a run through the task door ([roster-task-pool.md](roster-task-pool.md)) and pass its `runId`.
7. Close the overlay before typing in the composer: while it is open, letters are its keys (`p` pause, `s` shadow, `m` draw).
8. A local engine agent, end to end (driven 2026-11-20; needs no registry and no account):
   - **Folder.** `control-om om -- agent init vom-engine --dir <scratch>/scaffold` writes a chat agent's folder. Copy it, then from the checkout run a scratch Bun script that imports `writeFakeEnginePackage` from `packages/cli/test/_tool-engine-fixtures.ts` and calls it on the copy with `{ name: "@local/vom-engine", version: "0.1.0" }` (it adds `om-package.json` with the `engine` block, `tools.json` and `artifacts/<platform>`, a script that answers `echo_tool`). In `plugin.json` set `extensions["com.openmarket.chat"].executor` to `{"brains":["om"],"tools":["echo_tool"],"om_tools":["markets","backtest_sweep","memory_search"],"start_input_schema":{"type":"object","properties":{"thesis":{"type":"string"}},"required":["thesis"]},"budget":{"max_tool_calls":8,"max_backtests":72}}`, `capabilities.tools` to `[]` and `checks` to `{"reply":[],"work":[],"locked":["tools"]}`. In `agents/vom-engine/AGENT.md` set `kind: engine`, `tools: []`, `verify: {"reply":[],"work":[]}` and `locked: ["tools"]`.
   - **Refusals, no terminal.** `control-om om -- install <dir> --yes --format json` is `tool_engine_publisher_refused`; add `--allow-local-engine` and it is `terminal_required`. A copy with `no_such_tool` in `om_tools` is `schema_unsupported`; one with `order_place` is `local_engine_money_refused`.
   - **Card.** In a private tmux shell (`tmux -L <name> new-session -d -x 150 -y 50`, with the lane port exported and `om` defined as `control-om om --`): `om install <dir> --allow-local-engine`, read the card with `capture-pane`, press `y`. Then `control-om om -- agent show vom-engine` and `agent budget vom-engine`.
   - **Budget.** `agent budget vom-engine '{"max_backtests":36}'` saves; `'{"max_backtests":144}'` is `confirmation_required` outside the tmux shell and a `Raise  72 -> 144 backtests` card inside it (`Enter` on the default answers no).
   - **Run.** The daemon needs a model: restart the lane with `--env OPENMARKET_LLM_PROVIDER=openai-compatible --env OPENMARKET_LLM_BASE_URL=http://127.0.0.1:<fake>/v1 --env OPENMARKET_LLM_MODEL=fake`, where the fake streams one `tool_calls` delta (`function.name` `echo_tool`, `arguments` `{"text":"…"}`, `finish_reason` `tool_calls`) when the request has no `tool` message yet, text otherwise, and a last chunk with `choices: []` and `usage`. `control-om om -- agent start vom-engine --input '{"thesis":"<run id>"}' --format json` gives `runId`; `agent status <runId>`, `agent output <runId>` and `--tree` read it. Point the fake at `memory_search` or `markets` to see a listed om tool run, and at a name the package does not list to see `Unknown tool:`.

## Gotchas

- `om agent` has two generations of verbs. `list`, `show`, `configure`, `portrait`, `ps`, `cancel`, `create`, `init`, `try`, `eval`, `trust`, `start`, `status` and `output` are always there on the internal entry; `runs` and `pause` (retained work runs) still need `OM_DEV=1`, and `om roster` (list, measures) is `OM_DEV=1` only.
- A local engine build installs under its own package name: give the folder's `om-package.json` an `@local/<name>` name, and make the engine script's identity match it (`writeFakeEnginePackage` does both from its `name` option).
- An engine run on a lane whose daemon has no model fails at once with `Why: No LLM API key configured.` The model variables on the `om chat` call do not reach it; they must be on `control-om up`.
- `agent ps` truncates the run id on a row (`run_99b0`); `agent ps run_99b0` answers `Run was not found.` Take the id from `--format json`.
- A watch-door run's `Ask:` is the step's whole `<watch_header boundary=…>` envelope, not only the ask you wrote (README gaps).
- Typing into the composer while the agents overlay is open sends keystrokes to the list. On 2026-11-04 a typed sentence opened `Draw librarian? y/n`; answer `n` and check `agent list --format json` for stray `paused`/`shadow` flags.
- Creating an agent starts a `portrait` run on it at once; on a fake model it shows in RUNS as `! <name>  portrait  failed` with the agent's own prompt as the ask.
- A guest lane's chat shows `⚠ this install holds state from 1 other account (account guest_…)` on a fresh lane home; it is unrelated to the agents.
