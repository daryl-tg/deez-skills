## What it is

- A creator publishes one watch with blanks. Each person fills them and gets their own copy.
- `om install <pack> --set name=value` fills every open source, proves it with one real read, and shows a card: one row per blank, `Source: <publisher> · <who vouches>`, `Now: <field> <value>`.
- A second set of answers is a second watch (`haze-kuala-lumpur`, `haze-kathmandu`). The same answers again update the same watch.
- `om watch edit <id> --set name=value` changes an answer. `--refill-source <name> [--refill-way <way>]` moves a copy's source to the creator's next way. `--keep-source` and `--follow-source` pin or unpin a source across updates.
- `om watch show <id>` prints `From`, one row per answer and the source row. `om watch resolve <id> <source>` offers the creator's next way when the source breaks.
- `om watch blank <watch> <blank> …` opens a blank on a watch the person built. A list file's rows are each proved by one read. The watch file does not change.
- A copy's answers live in `<lane home>/accounts/guest/watch-overlay/<id>.json` (`answers`, `answer_labels`, `filled`). A creator's blanks live in `watch-blanks/<id>.json`.

## Gotchas

- Before #2716, installing a folder of four watches that share a blank (`@dboon333/weather-kit`) failed in chat and the TUI with `card face has 15 rows; 9 allowed for 4 member(s)` (card-budget.ts); the CLI install was fine. A dummy `OM_API_KEY` makes the install print a 401 for the registry receipt after a good install.
- `om watch import` takes a WatchSpec-shaped file and lands a page source with no sealed terms. Only `page-add --activate` seals it. `om watch resume` refuses.
- Any scratch script that imports product code outside `bun test` must export `OM_HOME` to a temp directory. With it unset the code reads the operator's real home and credentials. On 2026-11-05 a scratch call to the fill function ran one model request and one search on the operator's account that way.
- A bare lane has no relay, no registry sign-in and no model, so a stream share's yes, a registry install, `om want` and the by-search way cannot be driven on it.
- The registry page needs the registry's own asset handler in front of the server, or it renders unstyled and the picker script 404s. A scratch boot that wraps the test registry must call `serveAsset(req)` first.
- `om publish <dir> --dry-run` is the fastest check that a hand-written pack parses. A bad blank pointer exits 2 with `blank_fill_unresolved` and the path.
- A copy whose URL and recipe another watch on the same home already activated is told `om watch resume`, not the activation. That is correct: the terms are sealed per URL and recipe, not per watch.
- A watch imported with a page source and activated a moment later reads `unreachable … page-fetch is not answering` until its next check. The daemon polled it once before the seal. It clears on the next cadence.
- `om watch share --dry-run` prints its posts block twice. That is on main too.
- Do not drive the lane against a publisher while a live benchmark reads the same publisher. Both share its rate limit and the benchmark's tail times carry the load.
- A text blank's pattern key in a pack file is `pattern` (with `pattern_hint`), not `answer_pattern`; the latter is the summary's field in `om-package.json`.
- Matching order is exact key, exact label, folded key, folded label (2026-11-13). A list where one row's key folds to another row's label refuses at share and at install. Accents fold only on Latin and Greek letters: पटना never matches पाटन, й never matches и.
- Stop only the processes a run started, by pid or owned port. On 2026-11-19 both e2e lanes were SIGTERMed twice by a cleanup that killed by name. `om run` from a checkout re-spawns itself; stop what listens on the port.
- The registry worktree pins an older `@openmarket/contracts`; a recipe with a `log` source or `output.message` is refused until its `node_modules/@openmarket/contracts` is rebuilt from the om branch (`bun run build` in packages/contracts, then rsync). Never `bun install` there.
- Fixtures for local data are synthetic, under `~/dev-notes-artifacts/`; never point a lane at a real `~/.claude`.
- A page pack installed from chat reaches its step only after two more cards: the page switch-on (`watch_page_add {activate}`, never under the build grant) and the arm. An arm card before the switch-on fails `watch_page_activation_required`.
- To prove a step's report on the real model, the chat lane's daemon must run under the real HOME on a copy of the sign-in seed (the keychain resolves through HOME); a daemon on a synthetic HOME stands the sealed model down as not configured. Answer every folder blank with a rig path and remove the copied `vault.key` after.
- A feed that nothing reads holds its first item up to 30 minutes; an install whose `mine` blank names it is refused with `Read it now: om watch run now <watch>`.
- A kit member with a web search makes the whole install need an AI credential with hosted search: a keyless or openai-compatible home refuses before writing (`llm_not_configured`, `search_lane_unsupported`), `--preflight` included. Prove a kit install with a search member on a signed-in home.
- Rows a poller delivered while `om install` was still writing could fail `database is locked` (runner.log `[event-watch] ... database is locked`) and land as `outcome='error'` rows with no title, never re-read; seen 2026-11-26 on the weather-kit Tokyo install (25 of 72 tide hours). Since #2739 (`b08fb4c76`) the daemon's writes wait for the lock, a poller or feed delivers again what it could not store, and `om watch show` names any loss on the source's Status row, `2 items failed to store` (error rows of the last 24 hours whose text holds `database is locked`). The fix is source only here; count leftovers with a read-only `sqlite3 'file:om.sqlite?mode=ro'` query on `watch_history` grouped by `source_name`.
- A list on a poller, X or search source failed every row before #2730 because the slot was treated as a feed; X and search are still treated that way.
