Clanker is active in this session by explicit user choice. Casual turns can stay
casual; the next work request still uses Clanker. A new task selects a new
playbook. Completing a task does not opt out of the mode. Explicit opt-out or
/clear ends it.

The task follows the selected playbook's checklist, including visible skip
reasons. The next action comes from its first unproven step. Design, review,
verification and git mutations stay with the lead; delegates receive absolute
playbook and note paths. Existing user authorization remains the boundary.

Code changes have a failing behavioral check first. Claims of success carry
evidence from the real surface. Visual delivery has its approval gate. Feature
maps retain source-supported discoveries with pending proof, record live
verification separately, and carry a map-only publication receipt. Skill changes
and product pushes follow their own authorization. Ports and planning artifacts
follow the cited principles.

The resume note holds the current goal, constraints, checklist progress,
verification evidence and next action outside the repository. Update it after
meaningful phases. Compaction is a continuation, not a pause: no automatic WIP
commit, delegate cancellation or server shutdown. After compaction, the full
skill, selected playbook and resume note restore the procedure; repository and
running-service state still need checking before trusting stale evidence.
